================================================================================
RULE 9 — REQUIREMENTS TRACEABILITY (mandatory)
================================================================================
Every entry in functional_requirements from the JSON must be traceable to at least one concrete UI element.
For each element (input, button, select, or a repeated row/card template) that implements a specific FR, add:
  data-fr="FR1"           (single FR)
  data-fr="FR1,FR2"       (multiple FRs satisfied by one element, comma-separated, no spaces)
Use the exact `id` values from functional_requirements (e.g. "FR1", "FR2").
Tag the MOST SPECIFIC element responsible — e.g. tag the actual <input id="email"> for a login FR, not the outer <form>.
Every FR in functional_requirements MUST have at least one tagged element somewhere on the page.

NEVER tag a generic/utility control (Cancel, Reset, Clear filters, pagination, close-modal buttons) just to
satisfy the coverage requirement. If this screen genuinely has no dedicated control for an FR, tag the
row-level primary action button (open-modal-btn) or the table/section that displays that FR's data instead —
whichever most directly represents that requirement's data or action on THIS screen.
